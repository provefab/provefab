## Authorization and evidence
The user authorized testing then integration if conclusive, and explicitly approved per-repository protected path declarations and network-free gates until stricter local isolation is available. Native macOS probes: ../sandbox-audit-2026-10-13/RAPPORT.txt (relative to repository parent). Command guards alone fail for scripts, child processes and rewritten gate dependencies. Tested Codex 0.162.1, Claude 2.1.296 and Anthropic SRT 0.0.79.

## Scope budget
Exactly one shared sandbox policy, three worker adapters and the existing gate runner. No VM service, deployment, global package installation, PR publishing, model gateway or new permission UI. Unsupported or unavailable required enforcement must fail closed. Existing guards stay as defense in depth. No runtime fallback to unsandboxed execution.

## Policy
- Network denied by default. Explicit per-repository allow_local_network applies to gates (where tests need bind); worker commands remain strict. This narrower exception is chosen because workers can defer network-dependent tests to gates. On all platforms this option must currently refuse before launch: SRT allowLocalBinding also permits non-loopback inbound listening, which exceeds the authorization; loopback-only behavior is not verified on Linux either. Reopen when a verified loopback-only runtime is available, per the user’s explicit choice. Document that localhost includes services outside the sandbox.
- Only the task worktree and a dedicated per-run <session>/sandbox-tmp directory are writable by commands. SRT implicit shared temp/cache write paths are denied; CLAUDE_CODE_TMPDIR and TMPDIR/TMP/TEMP point to the private temp. Session/config/plugin/runtime files and validation paths are immutable. Read-only stages get no worktree writes.
- Deny reads of Provefab credentials, databases, worker auth directories, normal CLI auth directories, SSH/Git/cloud credentials and configured extra secret paths. No claim of isolating every possible host secret: the policy is an explicit deny list, and environment variables are a separate channel to sanitize.
- Codex uses native named filesystem/network permissions, approval_policy=never, no legacy --sandbox combination. Child environment must not expose host credentials.
- Codex support is pinned to reviewed0.162.1 and inspectable personal/API file authentication. System/managed/cloud policy sources and unsupported host helpers refuse before startup. Implicit project documents, bundled/cloud skills and Pi implicit context discovery are disabled; unsupported custom automatic sources refuse. Explicit trusted stage prompts remain. Codex stock .system cache can remain only as a real directory under an otherwise empty skills root, with its loading disabled. Native patch operations retain Codex's OS-sandboxed filesystem helper; no multi-file transaction atomicity claim.
- Final review ruling: every Claude stage temporarily refuses before filesystem preparation or any host version/auth probe. The implicit host memory/rules boundary is unverified even for clean personal profiles and NoTools. Direct users to Codex/Pi, never delete state. Reopen only with exact-source controls compatible with authentication/hooks and actual supported-stage evidence. This supersedes the earlier narrow 2.1.296 accepted-mode design.
- Pi Bash executes through SRT using the installed Pi tool factory; every route enabling shell execution must be covered or refused. Model API auth remains outside shell sandbox. Pi exposes sandboxed Bash for file operations; Claude stages refuse; native file tools with a separate pre-operation guard are refused because concurrent symlink changes bypass that check. Structured output remains available. Reopen specialized file tools only with enforcement on their actual file operation.
- Gate command strings remain in trusted Provefab config; their scripts and dependencies are protected explicitly. Use an explicit per-repository protected_paths list (workspace-relative paths or absolute external paths), and deny_read for additional host secrets. The user explicitly approved this approach. Empty protected_paths means no claim of immutable validation. Documentation must say that every script, test config, lockfile and dependency that defines success must be declared or live outside the worktree. Do not auto-discover a supposedly complete dependency closure.
- SRT must be provisioned separately outside the worktree; document exact tested version. Missing/invalid config or unsupported platform cannot report passing gates or launch an unsandboxed command.

## Acceptance evidence
Real commands, not only generated JSON: Python HTTP and curl with proxies bypassed, child secret read and symlink, Git local push removing GIT_CONFIG and hooks, protected script/config edits, valid workspace write, strict/local bind tests, runtime missing marker absent. Use only fake secrets and local fake remotes. Require at least one real supported worker command and one actual integrated gate execution. Claude must universally refuse before host version/auth/stage invocation even with a clean profile; fake markers and the existing native fixture assert the implicit-context boundary reason. Trusted adapter input regressions must reject external aliases whose resolution crosses either writable root, including absent secret leaves, while stable external aliases remain accepted. Linux results must be labelled unverified unless exercised. Tests do not prove immutable transitive dependencies unless explicitly included in protection.
