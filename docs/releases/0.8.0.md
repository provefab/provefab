# Provefab 0.8.0

Native execution policy now applies to repository checks and supported worker commands. Missing or unverifiable enforcement stops execution. Network access is denied, including package downloads and local listeners. Provision check dependencies before starting tasks.

## Upgrade from 0.7.0

1. Provision [SRT](https://github.com/anthropics/sandbox-runtime) separately, outside writable worktrees, with its dependencies in trusted directories. Minimum supported version: 0.0.79. SRT is not bundled with Provefab.
2. Configure `[repos.sandbox]` for every repository. Set `runtime` to the trusted SRT executable and explicitly declare `protected_paths`: validation scripts, tests, configuration, lockfiles, fixtures and every supporting dependency that defines success. Protecting an entrypoint does not protect its dependency closure. An empty list protects no validation harness. See [Configuration](../guide/configuration.md#repossandbox-native-execution-policy).
3. Remove or replace every `claude-code` model block in your catalog, including blocks generated by `provefab init`. All Claude stages are temporarily unavailable, including clean profiles and NoTools, and refuse before host version/auth probes. The implicit host context boundary remains unverified. Select Codex or Pi; keep user authentication and state intact. Login and doctor success do not establish stage support.
4. Codex requires exactly 0.162.1, an inspectable personal file login or API key and the supported dedicated untrusted profile. System, managed and cloud policy sources are refused. See the [worker restrictions](../guide/configuration.md#repossandbox-native-execution-policy) before running tasks.

## Verified scope and limits

On macOS 26.6.2 (Apple Silicon), real core gates and Codex 0.162.1 commands were exercised with SRT 0.0.79. Pi 1.0.3's installed Bash tool factory was exercised through the actual extension and SRT, without a Pi model call. Pi exposes sandboxed Bash for file operations; direct file/search tools are disabled. Linux native enforcement remains unverified; Linux builds and tests do not establish that boundary.

These are explicit path protections, not isolation from every host secret. An ordinary Codex patch completed and a protected patch was refused by the hook; no dedicated patch race experiment or multi-file transaction atomicity is claimed. See [Security](../guide/security.md) and the [native validation evidence](../superpowers/native-sandbox-validation.md) for prerequisites, commands and limits.
